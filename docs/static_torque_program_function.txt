OpenArm V1：tools/static_torque 文件功能说明
更新日期：2026-10-15

一、工具目录的用途

Ubuntu 项目位置：
/home/lsk/openarm_v1_ws/src/openarm-v1-project/tools/static_torque/

Windows 项目位置：
D:\Projects\openarm-v1-project\tools\static_torque\

本目录用于七关节右臂的通信诊断、静止姿态力矩采集、MuJoCo 模型检查和离线比较。
机械臂为 OpenArm V1，仅有 J1～J7，已移除 J8 电机和夹爪。
这些工具独立运行，不是 ROS 2 控制节点，也不是强化学习训练程序。

总体工作流程：
实机只读诊断 → 保存起始角度 → 模型检查并生成运动计划
→ C++ 程序按计划运动、保持和采集 → Python 离线比较真实反馈与模型重力。

二、主要程序

1. openarm_static_torque.cpp

完整的 C++ 实机通信和采集程序，需要编译后运行。
通过 Linux SocketCAN 与 can0 上的 J1～J7 电机通信。
读取七关节的角度、速度、反馈力矩、温度、电机状态和接收时间。
检查通信超时、接收队列丢包、时间质量、跟踪误差及配置的报警阈值。

运行模式：
--diagnose：只读诊断，约 10 秒，不发送使能、失能或运动指令。
--plan 路径 --execute：读取运动计划；输入 RUN_STATIC 后才开始使能和运动。

运动采集流程：
重新核对起点 → 预装当前姿态目标并核查状态 → 使能
→ 缓慢转移到目标姿态 → 等待稳定 → 记录数据 → 测试下一姿态
→ 返回起点并保持 → 承托后输入 SUPPORTED → 退出并尝试失能。

控制周期为 50 ms，不是 20 ms，不保证硬实时。
Ctrl+C 或运行故障时会尝试失能，需依靠既有防跌落保护承接下落。
软件力矩报警不是电机固件硬限流，也不保证瞬态力矩不会超限。

2. check_model.py

纯离线 MuJoCo 模型检查程序，不访问 CAN，不控制实机。
检查模型网格资源是否存在、模型能否加载。
打印自由度数量、七关节名称、模型限位、阻尼和摩擦参数。
可读取诊断 snapshot.json，在记录角度下计算模型重力力矩、静止被动力及接触情况。
如果未指定 snapshot，则检查模型零角度；这不是给真实电机发送零位指令。
当前检查按方向全部 +1、零点偏移全部 0 的暂定映射进行，不代表零点已准确标定。

3. torque_model.py

纯离线模型规划和数据比较程序，不访问 CAN，不控制实机。

prepare 功能：
读取配置、起始快照和姿态 CSV，检查模型关节映射、名义路径、角度裕量、
模型接触、静止被动力及重力力矩余量，生成 plan.json 和冻结模型 model.mjb。
路径采用离散取样检查，不是连续碰撞保证，不能判断未建模的实物障碍。

compare 功能：
读取实机采集目录，筛选静止且反馈质量合格的采样。
使用每一行实际测得的七关节角度，而不是目标角度，计算模型重力。
设置模型速度为零，读取 qfrc_bias 的静止重力项并转换到对应电机坐标。
输出逐采样力矩差，以及各姿态、各关节的均值、标准差和 RMSE。
核对冻结模型 SHA256 和 MuJoCo 版本，避免比较时模型被替换。
未完成实验或样本不足会标为数据集不完整，不自动给出机械臂精度 PASS。

4. prepare_local_pilot.py

首轮小范围探索性试验的离线准备工具，不访问 CAN，不控制实机。
沿用用户已验证可稳定保持的增益：
KP = [35, 35, 20, 20, 6, 6, 6]
KD = [4, 4, 2, 2, 0.8, 0.8, 0.8]

读取最近成功的 can0 诊断，要求快照不超过 3 分钟，且诊断末尾角度稳定、七关节失能。
自动生成 15 个采样姿态：起点；J1 正向 1°、回起点；J2 正向 1°、回起点；依次至 J7。
每次只有一个关节的目标偏离起点，每个稳定姿态采样约 3 秒。
名义转移速度不超过 0.005 rad/s，约 0.29°/秒。
进行模型路径检查后生成本次独立配置、姿态表、冻结模型和运动计划。

这是局部试验，不授权全范围运动。
零点不确定性仍保留 null，模型质量和完整实机行程不标为已核实。
未知零点误差不能当作零误差，也不能据此声称实际碰撞裕量有保证。
局部试验仍保留通信、状态、温度、速度、跟踪误差及软件力矩报警检查。

三、配置和姿态文件

1. safety.template.json

通用配置模板，包含模型路径、关节映射、零点偏移、限位、KP/KD、
速度、温度、力矩报警和稳定采样条件。
未核实内容留空，不可直接用于正式运动。

2. safety.model_pending.json

已填写当前模型路径、七关节名称和 XML 模型限位的配置草稿。
其模型限位不等于已核实的实机安全限位。
未确认的增益、保护值等仍留空，不能只修改确认标志来启动运动。

3. poses.template.csv

通用姿态表模板，一行一个姿态。
pose_id 为姿态名称，q1_rad～q7_rad 为七关节目标角度，单位 rad。

4. safety.local.json、poses.local.csv（如果自行创建）

用于通用 prepare 流程的实际配置和姿态表。
局部 1° 试验使用 prepare_local_pilot.py 自动生成的独立文件，不必依赖这两个文件。

四、构建与环境文件

1. CMakeLists.txt
描述 C++ 程序的构建方式、C++17 标准、线程库和 nlohmann_json 依赖。

2. build/
编译生成目录，包含可执行文件 build/openarm_static_torque。
修改 C++ 源文件后需要重新编译；只修改 Python 文件不需要编译 C++。
没有修改 C++ 代码时，重启电脑后无需重新编译。

3. requirements.txt
Python 依赖列表，当前固定 mujoco==3.3.7。

4. .venv/
本工具的独立 Python 虚拟环境，包含 MuJoCo 等依赖。
通过 .venv/bin/python 运行离线工具，避免混入系统 Python 和 ROS 环境。

5. COLCON_IGNORE
空标记文件，使 ROS 的 colcon 构建跳过本目录。

6. .gitignore
排除 build、.venv、Python 缓存及部分本地配置等，避免提交到 Git。

六、模型和实验数据的位置

模型在项目的 models 目录，不在 tools 中：
/home/lsk/openarm_v1_ws/src/openarm-v1-project/models/openarm_v1_right/
  openarm_v1_7dof.xml
  meshes/

XML 与 meshes 必须保留相对目录关系。

计划与实机采集数据统一保存在：
/home/lsk/experiments/torque_compare/

常见子目录：
diagnose_<编号>/：只读诊断。
pilot_<日期时间>/：局部试验准备结果，不是实际采集数据。
static_<编号>/：实际运动和静止姿态采集结果。

主要输出文件：
samples.csv：全过程七关节角度、速度、力矩、目标角度、温度、状态和时间信息。
  q1～q7：实际角度，rad。
  dq1～dq7：反馈速度，rad/s。
  tau1～tau7：按协议解码的电机反馈力矩，Nm。
  cmd1～cmd7：该行记录的目标/参考角度；诊断模式中不表示发送过运动指令。
  rx1～rx7：各关节的内核软件接收时间，不是电机硬件测量时间。
  status1～status7：电机状态，0 为失能，1 为使能。
  mos1～mos7、coil1～coil7：电机反馈温度字段。
  stable：是否标记为有效静止采样；诊断行的 0 不表示通信失败。
timing.csv、timing.csv.jsonl：通信耗时、接收质量、重试和异常诊断。
snapshot.json：起始实测角度和电机参数。
metadata.json：本次模式、参数、计划及完成/中止信息。
plan.json：运动计划，包含起点、姿态列表、配置和模型来源。
model.mjb：规划时冻结的编译模型。
pilot_config.json、pilot_poses.csv：局部试验自动生成的配置和姿态表。
comparison/comparison.csv：每个有效采样的真实反馈与模型重力比较。
comparison/summary.csv：每姿态、每关节的统计结果。
comparison/report.json：数据完整性、模型 hash、零点和力矩解释限制。

七、使用时的关键区别

1. C++ 源文件需要编译，实际运行的是 build 中的可执行文件。
2. Python 模型检查、生成计划和离线比较不会控制真实机械臂。
3. 只有 C++ 的运动模式，并输入 RUN_STATIC，才开始使能和运动。
4. 失能状态的近零反馈力矩，不能用来验证自由空间重力模型。
5. 电机反馈力矩是报告的估计值，不是独立力矩传感器测量值。
6. 模型重力不包含全部实机摩擦、动态惯性或外接触作用。
7. 差值可能来自零点、方向/单位、质量/质心、摩擦及电流到力矩换算等，不能全部归因于模型。
8. 正常采样时，外部承托不能承受连杆载荷，否则会改变所需电机力矩。
9. 源码和说明可以由 Git 管理；编译结果、虚拟环境及原始实验数据分别保存。
