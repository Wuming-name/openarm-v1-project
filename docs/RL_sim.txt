OpenArm V1 七关节点到点 PPO 仿真训练说明
==================================================

一、本次目标
本包只做 MuJoCo 仿真，不打开 CAN，不运行真实机械臂。
适用模型：右臂 V1，只有 J1～J7，没有 J8 和夹爪。

起始实际关节角 A（弧度）：
[0, 0, 0, 0.4, 0, 0, 0]
定义终点的关节角 B（弧度）：
[-0.3, 0.3, 0, 0.6, 0, 0, 0]

与 A 相比，B 的 J1 改变约 -17.19 度，J2 改变约 +17.19 度，
J4 改变约 +11.46 度。B 的 J4 绝对角度为约 34.38 度。
这里采用已讨论的 J4=0.4 起点，而不是更早提出的 J4=1 起点。

在此次实际加载的 XML 中，ee_site 的模型基坐标位置为：
A：[0.08411436, -0.15349846, 0.27905038] 米
B：[0.00407471, -0.27119610, 0.29846617] 米
两者直线距离约 0.143653 米，即 14.365 厘米。
以 prepare.py 在你的模型上重新计算的结果为准。

训练目标是让 ee_site 到达 FK(B) 所定义的固定空间位置并停稳。
不要求七个最终角度严格等于 B，不要求末端朝向与 B 一样。
七自由度冗余意味着可能存在其他满足末端位置的关节姿态。
本次只训练一个固定目标，不代表可以输入任意新目标直接到达。
模型 ee_site 是虚拟测量点；其物理位置和实机零点仍需之后校准。

二、成功条件
末端与目标的距离小于 0.02 米；
所有实际关节速度绝对值小于 0.02 rad/s；
所有目标角度积分器速度绝对值小于 0.002 rad/s；
以上条件持续 10 个策略步，也就是约 1 秒，且没有保护故障。
单回合最长 45 秒。故障或成功会结束回合，超时会截断回合。
2 厘米是此轮仿真任务的验收尺度，不是实际机械臂定位精度承诺。

三、为何需要新程序
旧环境在重置时把实际角度和 PD 目标角度设为相等，前馈为零。
在重力下，这会先下沉，再建立 PD 误差力矩，可能立即触发速度保护。
新环境只在每回合重置时，利用当前随机化模型的静止负载，计算一次
初始 PD 目标角度偏置，然后在保护开启状态下保持 1 秒并验证稳定。
它表达“虚拟机械臂已经在 A 附近稳定保持”，不模拟实机上电使能过程。
之后不会持续给策略增加重力补偿，前馈指令仍为零。
这是一种使用模型信息的初始化，实机无法直接照搬该过程。

另外，PD 目标角度包含支撑负载的偏差，不等于实际姿态。
新程序对目标参考路径检查角度范围和模型接触，对实际姿态检查
静止负载余量，并在每个物理积分步检查实际力矩、速度、跟踪及接触。
没有提高 KP、KD 或力矩报警值。
参考角度相对 A 的允许范围设为每关节 ±0.40 rad；实际角度范围为
每关节 ±0.45 rad，并同时受各关节自身上下限及 0.04 rad 边距约束。
这是本次仿真探索范围，不是对实机工作空间的批准。

四、策略的输入与输出
输入共 34 个数：
归一化实际关节角 7 个；归一化实际速度 7 个；
PD 目标角度与实际角度的误差 7 个；上一次动作 7 个；
固定目标三维坐标 3 个；目标与当前末端的位置误差 3 个。
训练观察噪声：角度标准差 0.0003 rad，速度标准差 0.001 rad/s。

输出共 7 个动作，均限于 [-1, 1]。
动作乘以 0.02 rad/s，成为七关节目标参考角度的期望变化速度。
以 0.04 rad/s² 限制该参考速度的变化，再每 20 ms 积分更新目标角度。
这里平滑的是参考速度，不是“实际速度直接加上动作”。

MIT 等效控制：
tau = KP * (q_reference - q_actual) + KD * (0 - dq_actual) + 0
实现中还模拟了既有 MIT 编码的截断量化，包括 nominal zero 的量化偏差。
MIT 的速度字段为零；参考角度积分速度不是 MIT 速度字段。
本版 PPO 不输出前馈力矩，也不输出独立的 MIT 目标速度。
这是先验证角度参考策略的版本，不是“角度加力矩双输出”的完整方案。
当动作降到零后，参考速度逐渐降到零，但已积分的目标角度仍保留，
因此 PD 仍可产生保持力矩。

KP：[35,35,20,20,6,6,6]
KD：[4,4,2,2,0.8,0.8,0.8]
力矩报警：[5,5,3,3,0.7,0.7,0.7] Nm
实际关节速度报警：各关节 0.15 rad/s
跟踪误差报警：0.16 rad
模型静止负载筛选上限：相应力矩报警的 60%。
这些是软件设置，不是厂家额定力矩。

五、时间与 PPO 采样
MuJoCo 物理积分：1 ms。
控制与目标角度积分：20 ms，每次执行 20 个物理积分步。
策略动作：100 ms，保持一组动作执行 5 次控制更新。
一个 PPO 采样步是一整个 100 ms 过程，记录 observation、action、
reward、下一次 observation 以及终止/截断状态。

默认 4 个环境，每环境收集 512 步，总 rollout 为 2048 个 transition。
此实现用 DummyVecEnv，4 个环境顺序计算，不等于 4 个 CPU 进程。
每次 rollout 分成每批 128 条，最多更新 10 个 epoch；target_kl 可能
提前停止该次更新。然后采集新的 rollout，旧数据不放入长期回放池。
网络：actor 和 critic 各有两层 128 单元，Tanh 激活；CPU 运行。
学习率 3e-4，gamma=0.995，GAE lambda=0.95，clip=0.2。

500000 步是所有环境合计的采样预算，不是每环境 50 万步。
按完整 rollout 收集，实际可能到 501760 步才停止。
模拟时间合计约 50000 秒，不等于墙上实际运行时间。
实际运行速度取决于 CPU、模型与逐步检查，先看训练输出 fps 再估计。
500000 步是第一轮预算，不保证网络已经学会。

六、随机化与奖励
训练每回合随机化：连杆质量及对应惯量系数 0.9～1.1；
阻尼、frictionloss 系数 0.7～1.3；起点各关节 ±0.005 rad。
模型中本来为零的阻尼/摩擦，乘系数后仍然为零。
这些范围是起步假设，尚不能覆盖已测得的全部实机偏差。
目标位置固定；重置的 PD 偏置按本回合模型计算。

奖励包括：末端接近目标的进展、距离惩罚、实际速度惩罚、
动作变化惩罚、偏离起点姿态的小惩罚；成功奖励 +10，故障惩罚 -20。
只看 reward 上升不足以验收，还要看独立评估的成功率、距离和故障。

八、Ubuntu 命令：复用原训练环境
以下命令全部在 Ubuntu 终端执行，不是在 Windows PowerShell。
原 openarm_rl_reach/.venv 已安装依赖时，直接复用，不需要重新安装。

cd ~/openarm_v1_ws/src/openarm-v1-project/tools/openarm_rl_reach_sim
PY="$HOME/openarm_v1_ws/src/openarm-v1-project/tools/openarm_rl_reach/.venv/bin/python"
"$PY" -c "import mujoco, gymnasium, stable_baselines3; print('依赖正常')"

首次准备配置与检查：
"$PY" prepare.py
"$PY" preflight.py --resets 20 --out preflight_initial

prepare.py 默认写 config.sim.json；已有同名文件时不会覆盖。
preflight 输出目录也不能已存在；重复检查用新名字。
只有 preflight 打印 PASS 后再运行正式训练。
preflight 包含一个利用模型负载设置终点 PD 参考的确定性基准，
只验证当前环境可完成此任务，不是 PPO，也不作为训练示范数据。

正式训练：
"$PY" -u train.py --config config.sim.json --steps 500000 --envs 4 --out runs/goal14cm_v1

训练后评估：
"$PY" train.py --config config.sim.json --evaluate runs/goal14cm_v1 --episodes 20

在 Ubuntu 本机桌面打开动画：
"$PY" view_policy.py --config config.sim.json --run runs/goal14cm_v1 --episodes 3

红色球体表示目标点。viewer 需要图形桌面，普通 SSH 无 DISPLAY 不可用。
窗口显示的是已训练策略，策略没学好时可能超时或故障退出，不能把
“可以打开模型”当作“完成训练”。

如果原虚拟环境不存在，则在本包目录新建：
python3 -m venv .venv
PY="$PWD/.venv/bin/python"
"$PY" -m pip install -r requirements.txt
然后再按上述顺序准备、检查、训练。

每次重新打开终端，都要先 cd 到本包目录并重新设置 PY 变量。
已有 runs/goal14cm_v1 时，用新名字，例如 runs/goal14cm_v2，避免覆盖。

九、停止和继续
正常使用 Ctrl+C 结束训练时，程序会尝试保存当前 policy.zip 和状态。
强制关机/杀进程不能保证 finally 保存执行；训练期间另有周期检查点。
从已保存的完整运行目录继续，使用新输出目录：
"$PY" -u train.py --config config.sim.json --resume runs/goal14cm_v1 --steps 200000 --envs 4 --out runs/goal14cm_v2
这里 200000 是额外采样预算。只接受相同模型和控制配置的权重。
不要用旧版环境的权重续训本版环境。

十、文件与结果
prepare.py：生成仿真配置，计算 A/B 位置并检查名义路径。
core.py：模型映射、MIT 等效力矩、参考积分、检查、配置合同哈希。
reach_env.py：Gymnasium 环境、重置、观察、奖励、成功判定。
preflight.py：多次初始化和确定性运动基准。
train.py：PPO 训练、继续训练和独立随机种子评估。
view_policy.py：显示已训练策略的 MuJoCo 动画。
config.template.json：本轮任务默认值；prepare 后生成本机 config.sim.json。
requirements.txt：Python 依赖。
test_contract.py：控制及初始化相关测试。
VERIFICATION.txt：交付前本机测试记录与未验证部分。
COLCON_IGNORE：避免 ROS colcon 将本目录当作需构建的包。

训练输出目录包含：
policy.zip：PPO 权重。
config.json / contract.json：此次配置、模型/控制哈希、种子。
progress.csv：PPO 统计，不是每毫秒物理轨迹。
training_status.json：预算是否结束、累计采样步数。
checkpoints/：周期检查点。

评估后新增：
evaluation.json：各回合成功/失败、末端距离、故障、两类成功率。
evaluation.csv：每个策略步的实际角度、速度、末端距离和故障。
训练不会把所有物理积分数据写盘，以免文件过大。
preflight 的 baseline.csv 包含确定性基准每 20 ms 的角度、速度、
参考角度、计算力矩和距离；这是仿真值，不是实机测量。

十一、验收与后续
先完成名义及随机化评估；目标可定为两类均至少 19/20 回合成功，
没有接触/力矩/速度/数值故障，且成功后的动作确实停稳。
20 次名义评估的环境相同、确定性策略相同，不能当作 20 个独立任务。
独立随机种子评估也只验证当前固定目标和所选随机化范围。
若不达标，先查看失败类型，不能直接取消检查来提高成功率。

即使达到上述条件，也只是仿真阶段通过。
实机部署还需校准零点、关节映射、末端坐标、MIT 力矩含义与执行时序，
设计真实的起点保持/初始化，并测试同一执行器控制下的模型差异。
本包不提供实机 --execute；不能将仿真初始化偏置直接作为实机上电命令。
